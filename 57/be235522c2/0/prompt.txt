## 2. Guest-owned data (db/schema.ts)

All in `/Users/hutusi/workspace/ai/david/monecraft/db/schema.ts`:

- **`user`** (23-35): `isAnonymous: boolean("is_anonymous")` (line 32, nullable — the anonymous-plugin flag), plus `skinId` (34). Guest rows = `is_anonymous IS TRUE` (the 0001 migration backfill uses `WHERE "is_anonymous" IS NOT TRUE` for the complement).
- **`profiles`** (85-99): `ownerId` NOT NULL → `user.id` **onDelete: cascade**; `profiles_owner_idx`. Guests can't own any: `createProfile` rejects `owner.isAnonymous` with `forbidden` (`lib/online/worldsService.ts:86`).
- **`worlds`** (107-134): `ownerId` NOT NULL → `user.id` **cascade**; `profileId` **nullable** → `profiles.id` **cascade** ("pre-profile rows … leave it null until claimed", lines 114-117); `kind: "sp-cloud" | "mp"`; **`saveBlob: bytea`** (line 128) — save blobs live **in Postgres, in this column**, keyed by world (one blob per world; not Vercel Blob, no per-user blob store). `worlds_profile_idx`.
- **`worldMembers`** (137-150): `worldId`→worlds **cascade**, `userId`→user **cascade**, `role: "owner"|"member"`, unique `(worldId, userId)`.
- **`worldInvites`** (153-166): `worldId`→worlds **cascade**, `createdBy`→user **cascade**, token unique, `expiresAt`/`maxUses`/`uses`.
- **Cascade summary**: deleting a guest `user` row cascades sessions, accounts, profiles (none for guests), owned worlds (and their `saveBlob`s), their memberships, and invites they created. So guest-owned rows are fully identifiable (`user.isAnonymous = true` → join on `ownerId`/`userId`/`createdBy`) and fully cascade-deletable.
- **Upgrade hook** — `lib/auth/server.ts:43-66` (`anonymous({ onLinkAccount })`): one transaction re-parents `worlds.ownerId`, `worldInvites.createdBy`, and `worldMembers` (with duplicate-membership `onConflictDoNothing`) before better-auth deletes the guest row. **It does not touch `profiles`** (guests can't have any). Comment: "the FKs cascade — so a missed table … would silently destroy data."
- Sessions API surface: `SessionUser = { id, name, skinId, isAnonymous }` (`lib/online/http.ts:10-17`); client mirror `lib/auth/client.ts:31,53-54`; UI gate `components/GameShell.tsx:317` (`onlineUser &amp;&amp; !onlineUser.isAnonymous` → account home).

## Key design calls (made once, referenced by the slices)

**D1 — GameShell "Play locally" door: a `browsingLocal` boolean, not a new screen variant.**
The root render at `components/GameShell.tsx:317` is already a fall-through (not a `screen.name` branch), so the door is a sibling piece of state, not a screen:

- `const [browsingLocal, setBrowsingLocal] = useState(false)`.
- Root render becomes: `if (onlineUser &amp;&amp; !browsingLocal) return &lt;AccountProfileSelect … onPlayLocally={() =&gt; setBrowsingLocal(true)} /&gt;`, else `&lt;ProfileSelect … onBackToAccount={onlineUser ? () =&gt; setBrowsingLocal(false) : undefined} /&gt;`.
- **Set** `browsingLocal = true` in two places: the Play-locally callback, and the session-resume path (`GameShell.tsx:196-198`) when a local-world pointer resumes — so a signed-in player who reloads mid-local-game and quits walks back out through the *local* menus (world-select → profile-select → "Back to account"), not an abrupt jump to account home.
- **Clear** it whenever `currentUser()` resolves null in `refreshOnlineUser` (`void currentUser().then((u) =&gt; { setOnlineUser(u); if (!u) setBrowsingLocal(false); })`) and via "Back to account". Sign-out from inside ProfileSelect's AccountPanel fires `onAuthChange` → this same path, so the stale flag can't survive a sign-out.
- ProfileSelect showing "Signed in as X / Sign out" while browsing locally is **desired**: it's the honest state ("you're signed in, browsing local worlds") and it gives cloud-save context. The way back is a new optional `onBackToAccount?: () =&gt; void` prop on `ProfileSelect`, rendered as a "Back to account" `mc-button` (`data-testid="back-to-account"`) directly under the `&lt;AccountPanel/&gt;` in **both** branches — the list view (`ProfileSelect.tsx:51`) **and the firstRun branch (`:36`)**, otherwise a signed-in account with zero local profiles that clicks Play locally is trapped on the create form.

**D2 — `playOnline` sign-in check: drop the pre-check entirely; sharpen the ticket-failure message.**
`playOnline` is only reachable from `OnlineWorldSelect` (account mode), so the user is signed in in every normal flow; the only failure left is an expired session, and `requestJoinTicket` already returns null on 401 which lands in the existing `connectError` alertdialog. Adding a `currentUser()` pre-check would cost a session roundtrip on *every* join to improve one rare message. So: delete line 172, change the message at `:174` to `"could not get a join ticket — are you still signed in, and is the game server configured?"`. `onlineProfile` becomes required (`OnlineProfile`, no null); `Screen` variant `play-online.onlineProfile: OnlineProfile`; quit routing (`:262-264`) collapses to always `{ name: "online-worlds", profile: screen.onlineProfile }`.

**D3 — WorldSelect cloud gating: a `cloudEnabled: boolean` prop.**
GameShell passes `cloudEnabled={onlineUser !== null}`. Inside WorldSelect: the `listOnlineWorlds` fetch (`:68-71`) runs only when `cloudEnabled`; the per-card gate at `:221` swaps `onlineUsed()` → `cloudEnabled`; server list filtered to `kind === "sp-cloud"` only (the `mpWorlds` split at `:154-157` dies). `onlineUsed` import removed from this file. Named `cloudEnabled` (not `signedIn`) because it gates exactly the cloud-saves UI, and GameShell stays the one place that decides what enables it.

**D4 — Join page: 4-phase state machine, reusing `&lt;AccountPanel/&gt;` as-is.**
`{ phase: "loading" } | { phase: "signin"; worldName: string } | { phase: "joined"; worldName: string } | { phase: "error"; message: string }`. Flow: `markOnlineUsed()` first (an invite click IS an online action, and without it GameShell's offline-first `refreshOnlineUser` gate would never probe the session after "Open the game" — this replaces the marking `ensureSignedIn` used to do) → `resolveInviteToken` (null → error) → `currentUser()` → if user, `acceptInviteToken` (false → "used up" error; already-member is idempotent-true) → joined; if no user, phase `signin`: render the world-name preview ("You're invited to **{worldName}** — sign in to join") + `&lt;AccountPanel onAuthChange={() =&gt; setAuthNonce(n =&gt; n + 1)} /&gt;`, with `authNonce` in the effect deps so a successful sign-in/up re-runs resolve→accept. AccountPanel needs no MenuScreen: its classes (`account-panel`, `menu-form`, `menu-field`, `menu-input`, `mc-button`, `account-error`) are global app CSS; render it inside the existing `.net-modal-box`, and do one visual check in the manual pass. Keep the client component, the `cancelled` cleanup, and the "Open the game" link.

**D5 — `auth.test.ts` replacement: keep a lean better-auth-on-PGlite integration test, don't fold it away.**
It's the only test constructing `createAuth` + `drizzleAdapter` against the real schema — exactly the seam that would break if better-auth minded the dropped column or the plugin removal changed session shape. Replace the guest-upgrade suite with ~2 tests: (1) `signUpEmail` creates a user + session cookie; `getSession` returns id/name/email and the `skinId` additional field; (2) `signInEmail` with a wrong password fails, right password yields a session. Keep the `returnHeaders` cookie technique and `closeTestDb` in `afterAll` (exit-99 leak).

**D6 — Migration 0003 mechanics.**
1. Edit `db/schema.ts` (drop `:31-32`) and `db/ddl.ts` (drop `:16`) — these MUST move together (PGlite mirror).
2. `bunx drizzle-kit generate --name retire-anonymous-guests` → emits `db/migrations/0003_retire-anonymous-guests.sql` (`ALTER TABLE "user" DROP COLUMN "is_anonymous";`), `meta/0003_snapshot.json`, and the `_journal.json` entry (idx 3).
3. Hand-prepend to the SQL, following 0001's hand-edit precedent, with a comment block:
   `DELETE FROM "user" WHERE "is_anonymous" IS TRUE;--&gt; statement-breakpoint` before the DROP. FKs cascade worlds/saveBlobs/memberships/invites.
4. PGlite paths need nothing more (fresh DDL each boot). Release note: deploy the new app **first**, then `bun run db:migrate` (old builds SELECT the column via the drizzle schema and would error post-drop; the new build never references it, and the still-present column is harmlessly ignored before migration).

**D7 — OnlineWorldSelect joined worlds.**
Filter (`:49-51`) becomes `world.kind === "mp" &amp;&amp; (world.profileId === profile.id || world.role === "member")`, with a comment: *joined worlds appear under every profile — membership is account-level, and their `profileId` is the host's*. The "Joined" label already renders (`:91`) and owner actions are already gated (`:97`). **Cap fix**: `atCap` (`:54`) must count only `worlds.filter(w =&gt; w.profileId === profile.id)` or joined worlds visually eat your create quota (the server counts only owned).

## Risks / gotchas

1. **Deploy ordering vs migration 0003** — old builds SELECT `is_anonymous` through the drizzle schema; new app first, migrate second (D6). Release-note it; the migration is deliberately destructive to guest data.
2. **better-auth after plugin removal** — the drizzleAdapter builds the user model from the configured schema + plugins; with the plugin gone it never touches `isAnonymous`, and the new `auth.test.ts` (D5) is the tripwire if that assumption breaks under an upgrade.
3. **`Client` type** — `ReturnType&lt;typeof createAuthClient&gt;` with no generic; verify `signUp.email`/`signIn.email`/`signOut`/`getSession` still typecheck (they're core, they will).
4. **`onlineUsed()` must survive** — it's offline-first (no session fetch on a cold menu), not a guest artifact. Callers after the rework: `GameShell.refreshOnlineUser:104` and `AccountPanel:30`. With `ensureSignedIn` gone, `markOnlineUsed` is set only by `AccountPanel.submit:56` and (new) the join page — the join page call is load-bearing (gotcha: forget it and the friend's "Open the game" lands on local menus while signed in).
5. **OnlineWorldSelect cap** — joined worlds must not count toward `atCap` (D7).
6. **e2e locator traps** — "Create" vs "Create account" vs "Create World": use `exact: true` on the profile form's Create (a Playwright-valid option; the past CI break was `{exact}` in a *component* test's testing-library call). Two-step "Sign in" (panel button, then form submit share the name) is safe because clicks are sequential.
7. **e2e timing** — sign-up → account home spans two network hops (sign-up, then `currentUser`); assert on "Your Profiles" with a 15 s timeout; distinct emails across contexts (one shared pglite process, single worker).
8. **`bun test` exit 99** — never gate on `bun test | tail`; the PGlite leak is expected, CI catches real leaks. New/rewritten PGlite tests must `closeTestDb`.
9. **Join-page AccountPanel unmount** — after sign-in the parent flips phase and unmounts the panel mid-`refresh()`; harmless in React 19, but keep the accept in the parent effect (nonce-driven), not inside `onAuthChange`.
10. **Legacy mp rows with `profileId: null`** — owned ones stay hidden from every profile list (pre-existing; migration 0001 backfilled real deployments), member-role ones now surface via the `role === "member"` arm — strictly an improvement.
11. **`connecting`/`connectError` modals** are only rendered on world-list screens — unchanged, since `playOnline` is now only reachable from `online-worlds`, which renders `netModals`.
