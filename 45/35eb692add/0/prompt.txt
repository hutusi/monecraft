### 4b. Vehicle boarding — **NOT practical end-to-end; keep as unit tests**

Boarding routes through `placeBlock` → `tryBoardAimedVehicle` (`lib/game/engine/GameEngine.ts:897`, within the `placeBlock` case `:879-906`). It requires **an existing vehicle the player is aiming at**. There is no seed hook: the replica never simulates vehicles (`state.vehicles = []` then only replicated in — `NetworkSession.ts:265-283`), and the host client IS a replica, so `window.__monecraft.engine` can't author a vehicle — a local `state.vehicles.push(...)` would be overwritten by the next server frame and wouldn't exist server-side to board.

To create one you must place it: `tryPlaceVehicle` (`GameEngine.ts:902`) needs a raft/ship item held and a right-click aimed at water, and water support is strict — `vehicleHasWaterSupport` requires Water below + Air at deck across all footprint corners (`lib/game/engine/systems/vehicles.ts:97-107`, gated by `canOccupy` `:121-133`). No server-side HTTP hook exists to spawn a vehicle (grep of `server/` shows only kick/pose/cmd, no vehicle-spawn endpoint). So an e2e would need: creative-give a raft, locate/craft water near spawn, aim precisely at the water surface, right-click to place, re-aim at the placed raft, right-click to board — all through real pointer math on a software renderer. **Verdict: leave to unit tests** (the boarding/mount/dismount logic already lives in `systems/vehicles.ts:135-205` with `server/room.ts` streaming `riderId` via `vp` poses and the rider's server-owned position via `SelfDelta.mountedVehicleId`, `NetworkSession.ts:382`). If any e2e coverage is wanted, assert only *replication of a vehicle pose* if one could be placed — but placement itself is the blocker.
